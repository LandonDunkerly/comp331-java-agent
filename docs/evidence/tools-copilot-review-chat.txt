Findings
There is a real escape path in Sandbox.resolve, but it is not the simple Fall case. A plain traversal like ../../etc/passwd is rejected by the guard at Sandbox.java:23-26.

The actual bypass is a symlink + .. pattern, because the code normalizes the path before checking real filesystem ancestry:

Sandbox.java:23 does root.resolve(userPath).normalize()
Sandbox.java:24-26 then checks only target.startsWith(root)
That means a path can look safe after normalization even when the real filesystem traversal escapes through a symlink.

Example inputs that bypass it

/tmp/sandbox/outer -> /etc

This passes the check at Sandbox.java:24

Which line allows each bypass?
In each case, the enabling line is:

Sandbox.java:23: normalize() collapses the dangerous symlink+.. sequence
Sandbox.java:24: startsWith(root) then accepts the normalized path
The check in Sandbox.java:27-31 only examines the nearest existing ancestor of the normalized path, not the real resolved path through the symlink, so it misses the escape.
