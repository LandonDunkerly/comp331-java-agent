It must not give the model arbitrary shell access. List JUnit test cases for the command allowlist (including attempts to inject extra commands or arguments), timeouts, failing tests, a missing pom.xml, Maven not being installed, and very long output. I’ve narrowed it to the security contract and the exact failure modes you need to cover; I’m checking the repo’s testing style one last time so the proposed JUnit cases match the project patterns.

Security contract
The tool should enforce a fixed allowlist:

command: exactly mvn
args: exactly ["test"]
no shell invocation at all
no ;, &&, ||, |, >, <, $(), backticks, or any other shell metacharacters
no extra flags such as -q, -Dtest=..., --debug, -X, or custom goals
no passing a single shell string like "mvn test; id" to bash or sh
This is the core rule that prevents arbitrary shell access. The check should happen before a subprocess is created, and the implementation should use a process list like ["mvn","test"], not a shell string.

The repo’s testing style is consistent with SandboxTest.java and ReadFileToolTest.java.
